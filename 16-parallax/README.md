# パララックス（スクロール連動の奥行き演出）

スクロールすると、背景・透かし文字・見出しが**それぞれ別の速さで縦に動いて**、奥行き（立体感）が出るヒーロー。

## 何を作ったか

各要素に「動く速さ」を `data-speed` で持たせ、スクロール量に応じて `translateY` でずらす。速さが要素ごとに違うので、ズレて動いて奥行きに見える。背景はゆっくり・手前の見出しは逆方向に速く、で深さを出した。

## なぜ・どこで使うか

ブランドサイト・ポートフォリオのヒーロー演出で使う。スクロールに動きを連動させる「スクロール演出」の基本形（canvas④・マーキー15と同じ"スクロール量を使う"系）。

## 実装のポイント（JS：主役）

- **`data-speed` × スクロール量**：`.js-parallax` の各要素について、`item.style.transform = translateY(scrollY * speed)`。`speed` は `data-speed`（文字列）を `Number()` で数値化（カウントアップの `Number(dataset.target)` と同じ）。
- **速度差＝奥行き**：背景 `0.3`／透かし文字 `0.4`／見出し `-0.5` のように**バラつかせる**ほど深さが強調される。マイナスは逆方向。
- スクロールのたびに全要素の位置を計算し直す（`window.addEventListener("scroll", ...)`）。

## 実装のポイント（HTML/CSS）

- **背景画像が「切れない」ための余白**：背景を `height: 160%` ＋ `top: -40%` で上下に大きくはみ出させる。**動く量（スクロール量 × speed）が、はみ出し量を超えると画像の端が見えて切れる**ため。speedを上げるなら、はみ出しも増やす（または speed を下げる）。
- **中央寄せは transform でなく flex**：透かし文字を `transform: translate(-50%,-50%)` で中央寄せすると、JSの `transform: translateY()` に上書きされて崩れる（day10マウスストーカーと同じ罠）。`inset: 0` ＋ flex で中央寄せすれば、JSのtransformと競合しない。
- **見せ方**：暗いオーバーレイで背景を落とし、白文字を主役に。巨大な透かし文字（`28vw`・`opacity: 0.06`）を奥に置いて奥行きの"層"にした。
- `.spacer`（高さだけの空div）でスクロール距離を稼ぐ（パララックスはスクロールするほど見える）。

## つまづき＆気づき

- **画像が切れた**：動く量がはみ出し量を超えてた。`height`/`top` を増やす or `speed` を下げると直る、という関係を理解した。
- **スクロールしたら透かし文字がズレた**：CSSの中央寄せ transform が、JSの transform に負けてた。中央寄せは flex に変更（CSS transform と JS transform は同じ要素で奪い合う）。

## a11y / perf メモ（上司目線）

- 透かし文字「WORKS」は装飾なので `aria-hidden="true"` 候補。常時スクロールで動くので `prefers-reduced-motion` で抑制する配慮も。
- `scroll` イベントで毎回 `transform` を当てている。重い場合は `requestAnimationFrame` で1フレームにまとめると滑らか（marquee15と同じ手）。
