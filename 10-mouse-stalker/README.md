# マウスストーカー（カスタムカーソル）

## 何を作ったか

マウスに追従するカスタムカーソル。**中心のドット（即追従）＋ 遅れて追うリング**の2層構成で、マウスを動かすとリングがヌルッと遅れて付いてくる。リンクにホバーするとリングが拡大＆白く塗りつぶされ、リンクには中心から外側へ伸びる下線が出る。ライブラリ不使用（バニラJS）。

## なぜ・どこで使うか

ブランドサイト・ポートフォリオなど“没入感”を出したいサイトの定番演出（Awwwards系で頻出）。プリローダー同様「場面を選ぶリッチ表現」。
技術的には **「`mousemove` で座標 → `requestAnimationFrame` で毎フレーム lerp → `transform` で反映」** という、追従・パララックス系インタラクション全般に効く型。

## 実装のポイント

- **追従の正体は lerp（線形補間）**：`currentX += (mouseX - currentX) * 0.15` を毎フレーム回す。目標との差の15%ずつ近づくので、遅れて追いつき・止まると減速する。**canvas④（スクロール飛び散り）と同じ式**で、別の場面でも使えると分かった。
- **ドットとリングの「ズレ」が高級感**：ドットは `mouseX/Y` をそのまま使い lerpなし（＝マウスに即追従）、リングは lerpした `currentX/Y`（＝遅れて追う）。この差が動きに深みを出す。
- **中心合わせは `translate(-50%, -50%)`**：要素を自分のサイズの半分ずらすことで、ハードコード（`-20px`等）せずに中心をカーソルへ合わせる。
- **拡大もlerpで滑らかに**：ホバーで目標 `scale` を 2.5 に変え、`currentScale` を lerpで追従。フワッと大きくなる。
- **「transformはJS管理、色・塗りはCSSクラス」の住み分け**：JSが毎フレーム `style.transform` を上書きするため、CSSクラスの `transform` は効かない（負ける）。なので拡大はJS側、白塗り（`background`）は `is-hover` クラス側、と役割を分けた。
- **中心から伸びる下線**：`::after` を `transform: scaleX(0)` で隠し、`transform-origin: center` ＋ `:hover` で `scaleX(1)`。中心から両側へ伸びる。`width` でなく `transform` で動かすのは、その方が滑らかで軽いから。
- **`mix-blend-mode: difference`**：カーソルが下の色を反転。文字に重なると色が抜けるリッチな見え方になる。

## つまづき＆気づき

- **リンクにホバーすると指カーソルが出た**：`<a>` はブラウザ標準で `cursor: pointer` を持ち、`body { cursor: none }` より優先される。リンクにも `cursor: none` を明示して解決。
- **CSSクラスの `transform` がJSに負ける**：毎フレーム `style.transform` を上書きしてると、`.is-hover { transform: scale() }` は効かない。拡大はJSの変数で管理する必要があった。
