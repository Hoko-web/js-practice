# 数字カウントアップ（lerpで減速）

## 何を作ったか

実績数字セクション。`0` から目標値（`1240` / `98` / `100`）まで、**最初は速く・最後はゆっくり**になりながらカウントアップする。グラデ文字＋青紫の光のにじみでリッチに。テーマは「lerp（線形補間）の理解を深める」。

## なぜ・どこで使うか

「導入実績 1,200社」「満足度 98%」みたいな**実績数字セクション**で実務頻出。ただ数字を置くより、スクロールで数字が動くと目を引く。
技術的には **lerp（線形補間）を"数字"に応用**した例。lerpは座標だけでなく、数値・スクロール量・色など何にでも効く汎用テクだと体感できる。

## 実装のポイント

- **lerpは座標専用じゃない**：`current += (target - current) * 0.05` を毎フレーム。マウスストーカーやcanvasと**同じ式**を、今回は「数字」に適用。残りの5%ずつ進むので、ゴールに近づくほど進む量が減り**自然に減速**する。
- **lerpの落とし穴＝ピッタリ到達しない**：lerpは目標へ無限に近づくが、計算上ちょうどには届かない（`1239.8…`で止まる）。そこで「残り（`target - current`）が `0.5` 未満になったら、`target` ちょうどを表示して `return`」で**手動で仕上げて止める**。
- **ループの停止＝`requestAnimationFrame` を呼ばない**：ループが続くのは毎回 `requestAnimationFrame(update)` で次を予約してるから。`return` でその手前を抜ければ次が予約されず**停止**する。
- **`requestAnimationFrame` の形**：`function update(){ …処理… requestAnimationFrame(update) }` ＋ 最後に `update()` で点火。`update`（カッコなし＝関数を渡す）と `update()`（カッコあり＝今すぐ実行）の違いがポイント。canvas・マウスストーカーと同じテンプレ。
- **`data-target` でゴールを持たせる**：HTML側に `data-target="1240"`。JSは `counter.dataset.target` で読むが、値は**文字列**なので `Number()` で数値に変換してから計算する。
- **見た目**：`Math.floor()` で小数を切り捨て整数表示。`font-variant-numeric: tabular-nums`（preloaderで学んだ）で桁のガタつき防止。グラデ文字は `background-clip: text` ＋ `color: transparent`。

## つまづき＆気づき

- **lerpは「無限に近づくだけで到達しない」**と知れたのが最大の収穫。マウスストーカーでは追従し続けるので気にならなかったが、「ちょうど1240で止めたい」場面では、自分で「十分近い」を判定して止める必要がある。
- **preloaderとの対比**：preloaderのカウントは `setInterval` の**等速**。今回はlerp＋rAFの**減速**。同じ「0→100」でも仕組みと印象が全然違う。
- `update` と `update()` の違い（カッコ＝実行ボタン、なし＝関数そのものを渡す）が腑に落ちた。
