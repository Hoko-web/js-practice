# ハンバーガーメニュー＋ドロワー（アクセシブル）

## 何を作ったか

スマホ定番の開閉ナビ。ハンバーガーボタンを押すと、暗幕がフェードイン＋右からメニューパネルがスライドイン。ボタンは三本線から×に変形する。閉じる方法は4つ（ボタン再クリック / 暗幕クリック / メニュー内リンク / ESCキー）。開いている間は背景スクロールを固定。スクリーンリーダー向けの `aria` も状態に合わせて同期する。

## なぜ・どこで使うか

**Web制作でほぼ全案件に出る最頻出部品**。レスポンシブ対応する以上モバイルナビは必須。今回は規約の標準型（`js-hamburger` / `js-drawer` / `is-open` / 閉じる3トリガー）に沿って作ったので、スターターに入れて使い回せる。

## 主役：`aria-label` と `aria-expanded`（スクリーンリーダー対応）

ハンバーガーは**見た目が線だけ＝文字情報が無い**ので、何もしないとスクリーンリーダー(SR)には「ボタン」としか伝わらない。そこで `aria` で「何のボタンか」「今開いてるか」を伝える。

- **`aria-label="メニューを開く"`** … ボタンの**名前**をSRに渡す。線だけのボタンに意味を与える。開いたら JS で `"メニューを閉じる"` に切り替え＝**次にすると何が起きるか**を伝える
- **`aria-expanded="false" / "true"`** … 操作対象（ドロワー）が**今開いているか**をSRに伝える。これが無いとSR利用者は「押したけど開いたの？」が分からない
- **`aria-controls="drawer"`** … このボタンが**どの要素を操作するか**（`id="drawer"`）を結びつける

ポイントは、**見た目（`is-open` クラス）と同じタイミングで `aria` も切り替える**こと。`openDrawer` / `closeDrawer` の中で、クラスと aria をセットで更新している。見た目だけ変えて aria を忘れると、SR利用者には状態が伝わらない。

## その他の実装ポイント

- **状態管理を関数にまとめた**：閉じトリガーが4つあるので、`closeDrawer()` に「クラス除去・aria戻し・スクロール解除」を集約。各トリガーは `closeDrawer()` を呼ぶだけ＝重複とズレを防ぐ。
- **閉じる4トリガー**：①ボタン再クリック（トグル）②暗幕クリック（`e.target === drawer` で暗幕自身のときだけ。day4モーダルと同じ）③メニュー内リンク ④ESCキー。
- **背景スクロール固定**：開いたら `body` に `is-locked`（`overflow: hidden`）を付け、閉じたら外す。付ける(open)・外す(close)をペアで。
- **CSS**：暗幕は `opacity` + `visibility` で隠す（`visibility` も切るのは、透明でも残る要素にクリックを奪わせない＆Tab対象から外すため）。パネルは `transform: translateX(100%)` で画面外に置き、`is-open` で `0` に戻してスライド。

## つまづき＆気づき

- **`closeDrawer` を二重に定義してしまった**：`function closeDrawer(){}` が2つあると、**後の宣言が前を上書き**する（巻き上げ）。結果、実際に呼ばれるのは後者だけになり、ドロワーが閉じなくなった。同名の関数宣言は要注意。
- **z-index のスタッキング文脈の罠**：`.header` が `position: fixed` + `z-index` だと独立した「箱」を作り、中の `.hamburger` の `z-index: 200` は箱の中だけの順位になる。外のドロワー(150)とは「箱同士（ヘッダー100 vs ドロワー150）」で比較されるため、ヘッダーが負けて暗幕に隠れた。ヘッダー側の `z-index` を上げて解決。「z-indexが効かない時は親の文脈を疑う」。
- **ネストの `&`**：`&.is-open`（同じ要素の状態）と `.drawer.is-open &`（親の状態で自分を変える文脈）の使い分け。
