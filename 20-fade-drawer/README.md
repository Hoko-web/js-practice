# フェードで開くドロワーメニュー（visibility + opacity）

## 何を作ったか

ハンバーガーで開閉するドロワー。開閉を **`visibility` ＋ `opacity` のトグル**で作り、フェードしながら「操作できる／できない」も正しく切り替わるようにした。閉じる操作は4つ（ハンバーガー再クリック・背景クリック・リンククリック・Escキー）。

## なぜ・どこで使うか

スマホのグローバルナビの定番。開閉の「見せ方（フェード）」と「操作可否・キーボード対応」を両立させるのが実務のポイント。

## 実装のポイント（CSS：今日の主役 visibility + opacity）

- **`display: none` だとフェードできない**（`display` は `transition` が効かない）。
- **`opacity: 0` だけだと透明でも要素が残る**＝クリックできてTabでも入れる（見えないのに操作できてしまう）。
- **`visibility: hidden` ＋ `opacity` の両方を `transition`**：`opacity` でフェード、`visibility: hidden` で操作不可＆Tab対象外に。閉じる時は `opacity` がフェードしてから最後に `visibility` が `hidden` に切り替わる（`visibility` は変化の最後まで `visible` を保つ仕様）。
- `.p-drawer` を全画面（`inset: 0`）の膜にして、中に右パネル。**z-index はヘッダー(100) ＞ ドロワー(90)** で、開いてもハンバーガーを押せる。
- ハンバーガー→× は `is-open` で3本線を `transform`（状態フックは規約どおり `is-open` に統一）。

## 実装のポイント（JS）

- **`openDrawer` / `closeDrawer` を関数化**：閉じる処理を4か所で使い回すため。
- **背景クリックで閉じる ＝ `e.target === drawer`**：クリックされた要素が膜そのものの時だけ閉じる（パネル内は閉じない）。
- **リンクは `querySelectorAll` ＋ `forEach`**：複数のリンク全部に「クリックで閉じる」を付ける。
- **`aria-expanded` / `aria-label` を開閉で同期**（読み上げに開/閉を伝える）＋ **Escキーで閉じる**。

## つまづき＆気づき

- **状態のフックは規約どおり `is-open` クラスに統一**（`aria-expanded` を直接スタイルの合図にする手もあるが、ハウスルールに合わせた）。
- `.is-open` のネスト位置を間違えて×アニメが効かなかった → 「ボタンが開いてる時、その中の線を指す」向きで書く。
