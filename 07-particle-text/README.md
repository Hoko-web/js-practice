## ① canvas基礎 ＋ ランダムドット

### 何を作ったか

canvas 全面に、白い小さなドット（4px角）を300個ランダムにばらまいた静止画。
パーティクル表現の土台となる「canvasに点を打つ」を最小構成で実装。

### なぜ・どこで使うか

普通のLP・コーポレートサイトは画像とCSSで足りるので canvas の出番は少ない。
ただしパーティクル背景・動く背景・署名パッド・画像加工・グラフ（Chart.js の中身）など、
「CSSでは無理なリッチ表現」で武器になる。差別化要素として持っておくと強い。

### 実装のポイント

- **canvasは「サイズが2つ」ある**のが最大の関門。
  - 中身の解像度（`canvas.width` / `canvas.height`、初期値300×150）
  - 見た目の表示サイズ（CSSの `width` / `height`）
  - この2つがズレると、小さい絵を引き伸ばして表示することになり**ボケる**。だからJSで合わせる（＝サイズ同期）。
- サイズ同期は `canvas.clientWidth / clientHeight` を使った。
  - `window.innerWidth` でなくこちらにした理由：**表示サイズを決めるのはCSSの仕事**、JSは**その結果を読んで合わせるだけ**、と役割を分けられるから。CSSの値を変えてもJS側が自動で追従する。
- `const ctx = canvas.getContext("2d")` … canvasに描くとき必ず最初に呼ぶ（2D用。3D=webglもある）。`fillRect` も `fillStyle` もすべて `ctx.` で呼ぶので、1回受け取って変数 `ctx` に入れて使い回す。
- `ctx.fillStyle`（色）は**ループの外で1回だけ**、座標 `x` / `y` は**ループの中で毎回**計算する。
  - 外に出すと `Math.random()` が1回しか走らず、同じ座標に300回重ね塗り → 1個に見えてしまう。「毎回変えたい値はループの中」。
- ランダムな位置は `Math.random() * canvas.width`。`Math.random()` は0以上1未満なので、幅・高さを掛けて画面全体に散らす。

### つまづき＆気づき

- 最初「何も描けない」状態になった。原因はCSSの `width: 100vh`（`vw` のタイポ）と、白ドットが小さくて見えていなかったこと。`console.log` でサイズを確認 → でかい四角でテスト描画、の順で切り分けた。
- `ctx` が何者か最初ピンとこなかったが、「**`fillRect` などの描画命令はぜんぶ `ctx` のもの。`getContext` でそれを受け取って使い回す**」と捉えたら腹落ちした。
